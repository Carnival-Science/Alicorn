# Issue #138: retained motion ownership and typed property targeting

**Reviewed:** 2026-11-16  
**Checkout:** `/private/tmp/alicorn-issue-201`

**Audit baseline:** Issue #138's runtime ownership, typed property targeting, and tests. The implementation follow-up is recorded below.

## Finding

The retained ownership and stale-handle core is implemented for **whole retained nodes**. Motion state is stored in an Alicorn-owned sparse sidecar, by value, and a handle carries runtime identity, `Node_ID`, and generation. Current motion targets are typed translation and opacity values, with a global bound of 1,024 owner records. Existing tests cover node removal/recreation, cross-runtime handles, release, owner capacity, repeated declaration coalescing, and a presentation-only frame that does not rebuild the application description or visit reconcile, measure, or layout.

The typed-property contract is **partial** relative to #138: there is no motion key for a visual part or property identity, and the motion sidecar has no general color property. A separate retained button hover-fill transition interpolates a scalar mix between two button styles; it is a constrained style feature, not a general typed color target. These findings follow the issue's goal, scope, and acceptance criteria in [#138](https://github.com/samanshaiza004/alicorn/issues/138).

## Ownership and lifetime

- `Runtime.motion_owners` is `map[Node_ID]Motion_Retained_Owner`. Each owner record stores translation and opacity response structs and sampled values directly; no application property pointer is stored. `Motion_Target` likewise contains `Motion_Vector2`/`f64` values and says it intentionally excludes a retained owner/handle. [Runtime sidecar](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/runtime.odin#L1993-L2009) · [owner record](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L202-L233) · [target value type](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_math.odin#L114-L128)
- `Motion_Owner_Handle` is `{runtime_identity, node, generation}`. Begin requires a nonzero, active retained node, allocates a process-wide runtime identity, returns the existing generation for an already registered owner, and otherwise increments the runtime-local generation sequence. The sidecar is capped at `MOTION_RETAINED_MAX_OWNERS = 1024`. [Handle and cap](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L13-L27) · [runtime identity sequence](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L478-L492) · [owner registration](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L604-L645)
- Every operation checks runtime identity, node/generation match, and that the node remains active. Subtree retirement deletes its motion record; explicit release deletes only the sidecar record and restores neutral composition. [Current-handle validation](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L705-L714) · [retirement and release](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L1458-L1486) · [reconcile retirement hook](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/reconcile.odin#L769-L780)
- Node identity hashes include the parent. Thus a keyed node moved to another parent normally receives another `Node_ID`; when the old node retires, its motion record retires too. This yields snap/recreate behavior; there is no cross-parent motion-transfer token/API in the inspected motion handle. ## Typed property targeting

- The low-level public paths are property-specific: `motion_target_translation` accepts `Motion_Vector2`; `motion_target_opacity` accepts `f64` and rejects non-finite/out-of-range values. Translation similarly rejects non-finite or out-of-supported-range components. Both accept a typed `Motion_Mode` (`Settle`, `Direct`, `Snap`). The thin `alicorn:ui` wrapper exposes corresponding translation/opacity calls plus a declarative `motion` request. [Translation API and validation](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L948-L1037) · [Opacity API and validation](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L863-L946) · [UI API](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/ui/ui.odin#L79-L153)
- The retained owner has one translation slot and one opacity slot. The handle and map are keyed only by `Node_ID`; neither carries a visual-part ID or a property key. Consequently, this API can safely animate those two copied values on a node, but cannot independently bind motion to multiple parts/properties of one node. [Owner slots](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L202-L221) · [Map key](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/runtime.odin#L1993-L1997)
- Visual parts do have their own identity and are stored separately, but motion does not consume that identity in its handle or owner map. [Visual-part identity and storage](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/runtime.odin#L81-L100) · [Visual-part attachment](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/visual_parts.odin#L10-L71)
- There is a distinct `Style_Transition_Owner`, also keyed by node, for button hover-fill transitions. Eligibility requires an opaque flat fill and unchanged text, material, shape, and physical height; it stores a style pair and scalar mix rather than a general motion property. `style_color_mix` interpolates the stored RGBA components directly; this path does not establish a named color space/gamut policy for the general surface/indicator color target requested by #138. [Separate style-transition record](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/style_transition.odin#L33-L54) · [Eligibility](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/style_transition.odin#L131-L150) · [Hover-fill transition](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/style_transition.odin#L214-L307) · [RGBA mix](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/style.odin#L751-L761)

## Sampling, description, and presentation

The declarative UI path queues one request per described node and replaces an earlier request for that same node. `end_frame` applies it after reconciliation/layout/semantic commit, so the complete subtree is known for Reveal checks. Once the record exists, `motion_tick` samples retained value state and requests presentation; it does not require the application to resubmit a property pointer or motion record. [Queue and coalescing](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L511-L601) · [Post-reconcile application](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/reconcile.odin#L1088-L1103) · [Sampling](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L1216-L1345)

`Motion_Presentation` exposes target and presented translation/opacity separately. Composition accumulates parent/child translation and multiplies opacity; the paint pass applies those values to cached commands. The documented initial input policy keeps hit testing and accessibility bounds at target geometry; `Follow_Visual` is an opt-in clip policy. [Presentation snapshot](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L170-L183) · [Composition](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/motion_retained.odin#L1489-L1507) · [Paint consumption and clipping](https://github.com/samanshaiza004/alicorn/blob/9c78ed63ad8ab938661edf2e2f4ff4fafb297e63/runtime/paint.odin#L215-L270)

## Implementation follow-up

The issue follow-up implements a deliberately bounded typed color property on a retained node:

- `Motion_Target.surface_color` is a value target with its own presence flag and theme response config. It does not retain a pointer into application state.
- `motion_target_surface_color` and `ui.motion_surface_color` use the existing generation-checked owner and analytic response modes. The declarative path queues color alongside translation and opacity and applies it after reconciliation.
- Color targeting is restricted to a solid semantic-surface fill owned by that node. Gradients, Button recipe surfaces, arbitrary paint commands, and per-visual-part color tracks remain unsupported. This keeps the target mapping unambiguous while making a third-party semantic surface animatable.
- Alicorn `Color` is normalized linear-sRGB. RGB channels interpolate componentwise in linear light, are validated in `[0,1]`, and are clamped again at presentation; straight alpha is held constant and must match the resolved fill alpha. A previously authored `Motion_Theme_Policy` may omit the new color config and receives the default response.
- `Paint_Command.semantic_surface_fill` identifies just the semantic fill, so color composition does not alter its stroke, focus outline, text, or descendants. This property is a paint/material value and can cause GPU upload work; the no-description/no-reconcile/no-measure/no-layout guarantee does not imply compositor-only color updates.
- `Motion_Interaction_Policy.Target_Static` names the current input contract. Hit testing, focus identity, pointer capture/activation, and semantic/accessibility bounds continue to use target geometry while translation changes paint. Reparenting releases the old motion sidecar; parent-local residuals do not transfer to new coordinates. Existing parent-scoped `Node_ID` identity independently retires and recreates ordinary moved keyed nodes.
- Retained color is canceled when its solid semantic-surface binding is removed, becomes a gradient, or changes alpha. Owner release restores the current style-resolved fill.

Regression coverage was added for declarative color target application after reconciliation, linear-sRGB sampling, constant alpha and gamut validation, Direct/Snap behavior, fill-only composition, motion-only stage counters, unsupported bindings and cancellation, static hit/semantic geometry with pointer capture, and reparented-owner retirement. `odin check runtime -no-entry-point` and `odin check ui` with the pinned Alicorn/AccessKit collections typechecked successfully; the test suites were not executed in this local pass.

### Remaining boundary

This closes the useful color-target seam without introducing an open-ended property registry. Motion remains node-owned, with fixed typed slots for translation, opacity, and semantic-surface fill. A general visual-part/property key, moving hit geometry, alpha animation, gradient-stop targeting, and renderer-specific effects are not implemented. A color motion frame may still incur paint upload cost; no performance claim beyond skipping application description/reconciliation/measurement/layout is made.
